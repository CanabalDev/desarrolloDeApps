API en ejecución

Gestión de usuarios y fincas

El backend está activo. Usa las rutas siguientes para consultar y administrar la información desde Kodular u otra aplicación.

Cómo enviar las peticiones

Para las solicitudes POST y PUT, envía un cuerpo JSON y agrega el encabezado Content-Type: application/json. Las rutas de consulta y borrado no requieren cuerpo.

Los errores se responden como JSON con un mensaje, por ejemplo: {"mensaje":"No existe el usuario solicitado."}.

Usuarios

MétodoRutaUso
GET/api/usuariosLista usuarios. Filtros opcionales: nombreUsuario, correo, nombre.
POST/api/usuariosCrea un usuario.
GET/api/usuario/{usuarioId}Consulta un usuario.
PUT/api/usuario/{usuarioId}Actualiza un usuario.
DELETE/api/usuario/{usuarioId}Elimina un usuario si no es propietario de una finca.
POST/api/usuarios/iniciar-sesionComprueba el nombre de usuario y la contraseña.

Crear usuario

{
  "nombreUsuario": "ana",
  "contrasena": "mi-clave",
  "correo": "ana@ejemplo.com",
  "nombre": "Ana Pérez"
}

Iniciar sesión

{
  "nombreUsuario": "ana",
  "contrasena": "mi-clave"
}

Responde {"autenticado":true} o, si no coinciden, estado HTTP 401.

Actualizar usuario parcialmente

En el PUT puedes enviar solo los campos que quieras cambiar. Los omitidos se conservan; si contrasena se omite o se envía vacía, se mantiene la contraseña actual.

{
  "correo": "ana.nueva@ejemplo.com",
  "contrasena": ""
}

Ejemplo de filtro: GET /api/usuarios?nombreUsuario=ana&correo=ejemplo.com

Fincas

MétodoRutaUso
GET/api/fincasLista fincas. Filtros opcionales: nombreFinca, propietarioId, pais, departamento, ciudad.
POST/api/fincasCrea una finca.
GET/api/finca/{fincaId}Consulta una finca.
PUT/api/finca/{fincaId}Actualiza una finca.
DELETE/api/finca/{fincaId}Elimina una finca.

Crear o actualizar finca

Para asignar propietario y capataz, envía sus identificadores. El capataz es opcional.

{
  "nombreFinca": "Finca Verde",
  "areaHa": 1.23,
  "areaM2": 12345.00,
  "propietarioId": "id-del-usuario",
  "capatazId": null,
  "pais": "Colombia",
  "departamento": "Antioquia",
  "ciudad": "Medellín",
  "produceLeche": true,
  "produceCereales": false,
  "produceFrutas": true,
  "produceVerduras": false
}
Respuestas habituales: creación HTTP 201, consulta/actualización HTTP 200, borrado HTTP 204, datos inválidos HTTP 400, elemento inexistente HTTP 404 y conflictos HTTP 409. Actualmente el inicio de sesión solo valida las credenciales; no genera token y las rutas CRUD no requieren iniciar sesión.
